- 状态：进行中
- 设计：`docs/design/shoot-flow.md` 第 2、3、4 节（先完整读）；视觉与文案规则沿用 `docs/design/miniapp-ux-v2.md` 第 3 节。
- 与 T024 并行；T024 会给 `PhotoOut` 加 `quality` 字段，本任务按“字段可能不存在”兼容（不存在就不提示）。

## 只允许改的文件
`miniapp/src/`。不改后端。

## 要求
1. 引导页 `pages/shoot-guide`（替代 `ShootGuide` 面板；`app.config.ts` 注册页面）：按设计第 2 节。示范插画用 CSS 画剪影（正确 1 个 + 错误 3 个：侧脸、头太小、背光），不用真人图片。常见问题默认收起。“下次不再提示”沿用原来的本地存储键。
2. 拍照页 `pages/camera`：按设计第 3 节。用 Taro `Camera` 组件，默认 `devicePosition="front"`；人像轮廓框与头顶线、下巴线；倒计时（关/3 秒，默认 3 秒，可取消）；补光（前置：`Taro.setScreenBrightness` 调到 1 并显示白色外圈，`onHide`/`onUnload` 恢复原亮度；后置：`flash`）；切换前后摄像头；左下角相册入口；拍照用 `CameraContext.takePhoto({ quality: 'high' })`。
3. 拍后确认：拍照页内的状态（不新开页面），大图预览，“用这张”/“重拍”。“用这张”后上传并创建照片（复用 `utils/pickPhoto.ts` 里的上传与创建逻辑，抽出“用已有临时文件创建照片”的函数；来源记为 `camera`），然后进入制作页（保持 T023 的第 1 步/第 2 步逻辑：首页“开始拍”不带规格，规格快捷入口带规格）。
4. 拍后即检测：上传返回的照片若有 `quality.level === 'fail'`，在确认界面显示原因与改法，“重拍”为主按钮、“仍然使用”为次；`warn` 在制作页顶部显示一条提示（可关闭）；`ok` 或字段不存在不提示。
5. 权限：相机权限被拒时显示说明、“去设置打开”（`Taro.openSetting`）和“从相册选”。
6. 入口：首页“开始拍”→ 引导页（勾选过“不再提示”则直接拍照页）；规格详情页和首页规格格子同样走引导页/拍照页，并把规格编码带到制作页。删除不再使用的 `ShootGuide` 面板代码。
7. 小屏和刘海屏：取景框和底部按钮避开安全区。
