# T027 拍照页实时姿态与光线提示

- 状态：进行中
- 依赖：T025（拍照页）已合入
- 背景：用户要求“通过拍照的引导让用户拍照姿势、光线及时做调整……提高通过率”。工具评估（2026-11-20，Opus）：
  - InsightFace：模型仅限非商业研究（README 原文），不用；
  - MediaPipe：模型许可不明、会上报数据、不能在小程序运行，不用；
  - **用微信小程序端上人脸能力**（VisionKit `wx.createVKSession` 人脸跟踪，或 `wx.initFaceDetect`/`wx.faceDetect` 配合 `<camera>` 的 `onCameraFrame`），图像不离开手机、免费。
  - 官方文档页为脚本渲染，未能抓取正文：**具体字段名、角度取值范围和单位、最低基础库版本以开发者工具里的类型定义（`@tarojs/taro` / `miniprogram-api-typings`）和真机为准**，代码里做好防御。

## 只允许改的文件
`miniapp/src/`（新增 `utils/faceGuide.ts` 等）。不改后端。

## 要求
1. **能力探测与降级**：优先 VisionKit 人脸跟踪（若可用且能拿到相机帧或自带相机），否则 `wx.faceDetect` + `CameraContext.onCameraFrame`；都不可用则不显示实时提示（保留 T025 的拍后检测）。探测失败、首帧超时（如 3 秒）也降级。不要因为检测失败影响拍照。
2. **节流**：每秒处理 4~5 帧；页面隐藏、拍后确认、倒计时期间暂停；离开页面释放（停止 listener、销毁 session）。
3. **判定**（纯函数放 `utils/faceGuide.ts`，写单元测试可用的纯逻辑，阈值集中成常量并注释）：
   - 人脸数：0 →“把脸放进框里”；>1 →“画面里只留你一个人”；
   - 正脸：yaw、pitch、roll 接近 0（按接口实际单位换算成角度，阈值约 10°；pitch 方向提示“下巴收一点/抬一点”，yaw“头往左/右转一点”，roll“头摆正”；注意前置摄像头画面镜像时左右要翻转）；
   - 距离与位置：人脸宽度占取景框宽度比例过小“靠近一点”、过大“离远一点”；人脸中心偏离框中心“往左/右/上/下移一点”；
   - 睁眼：用眼部关键点算眼睛纵横比，过小“请睁开眼睛”（关键点编号以实际返回为准，取不到就跳过此项）；
   - 光线：用帧数据算人脸区域平均亮度（过暗“光线有点暗，面向窗户或打开补光”，过亮“光线太强，换个位置”）和左右半脸亮度差（“左边脸偏暗，转向光源”）。
   - 每次只显示**一句**最优先的提示，优先级：人脸数 > 距离位置 > 正脸 > 睁眼 > 光线。提示变化做防抖（同一结果持续约 0.5 秒才切换），避免闪烁。
4. **界面**：轮廓框状态色（未合格中性、合格变绿）；提示语替换 T025 的固定提示位置；全部合格显示“很好，保持不动”。快门始终可按。
5. **自动拍摄**（开关，默认开，存本地）：全部合格且持续约 1 秒，自动开始 3 秒倒计时；倒计时中任一项不合格就取消并回到提示。
6. 文案遵守 `docs/design/miniapp-ux-v2.md` 3.6。
