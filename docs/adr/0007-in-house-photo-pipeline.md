# ADR 0007 自建照片处理流水线：专用抠图 + 不改五官的精修，服务商只做合规验证

- 状态：已采纳（2026-11-20）

## 背景
“把照片拍好看”是产品的核心，但后端此前只有占位实现：正式抠图未接入（fake 只能去纯色背景），按比例居中裁剪（不识别人脸），美颜是整图模糊加提亮。用户（产品负责人）要求按“专用抠图 + 传统图像算法精修”的思路自建，再用服务商的合规检测接口验证能否过检。

关键约束：广东等地的回执由官方系统检测，生成式 AI 改动五官、去痣会被判“非本人/合成”。

## 决定
1. **抠图**：本地 ONNX 推理 MODNet 官方权重（Apache-2.0，约 25MB，CPU 512px 约 0.2 秒）。上传时做一次，结果存为照片的抠图底片（沿用 `matting_file_id`）。BiRefNet（MIT）作为高精度备选，留待效果评估后决定是否引入。
2. **人脸**：OpenCV Zoo 的 YuNet（MIT）取人脸框和 5 个关键点；头顶位置取自抠图蒙版。
3. **裁剪**：按人脸定位（头部高度占比、头顶留白、水平居中），不再居中裁剪。
4. **精修只动光影和皮肤质感，不动几何**：
   - 自动光影（始终开启）：曝光、白平衡、左右脸亮度差（阴阳脸）校正；
   - 美颜（受规格 `beauty_max` 限制）：只在皮肤区域做保边平滑、LAB 空间去暗黄和局部提亮；眼、眉、鼻孔、嘴唇区域排除；
   - 祛痘：用户在小程序点选位置，后端对小半径区域 `cv2.inpaint`；不自动去痣；
   - 不做任何改变五官形状、位置、大小的操作。
5. **合规验证**：用服务商 `POST /idphoto/check`（0.012 元/次）验证。先做离线评估脚本，用测试照片批量跑流水线并调用检测，按美颜档位统计通过率，据此定默认参数；上线后再决定是否在办理回执前自动检测。
6. **拍后快速检测（免费、本地）**：上传后用人脸检测结果给出“没有检测到人脸、多人、脸太小/太偏、太暗/太亮、没正对镜头”等提示，返回给小程序。

## 不采用
- **BRIA RMBG-1.4 / 2.0**：非商用许可，商用需另购授权。
- **MediaPipe Face Landmarker**：模型文件许可未能确认，且官方说明 Tasks API 会向 Google 上报使用数据；服务端处理用户人脸时不引入。
- **生成式 AI 美颜**：会改动五官，回执过检风险高。
- **伪造相机 EXIF、叠加噪点以规避合成检测**：属于对官方检测的欺骗，不做。美颜强度以规格允许为准，不以“骗过检测”为目标。
- **服务商的制作/换装接口作为主流程**：效果与成本不可控，且与自建精修冲突；换装待自建流程稳定后再评估。

## 代价
- 服务器要承担推理算力（CPU 可用，单张约 0.2~0.5 秒）；模型文件不进 Git，部署时用 `scripts/download_models.py` 下载并校验。
- 精修效果需要用真实照片反复评估；测试照片只用开发者本人或已授权的照片，不进仓库。
