# ADR 0008 运营后台列表改用页码分页，小程序继续用游标分页

- 状态：已采纳（2026-11-20）

## 背景
CLAUDE.md 原规则“列表用游标分页”。运营后台因此只能“加载更多”。用户要求标准管理后台分页：显示总条数、跳到指定页、自选每页条数。游标分页不知道总数、也无法直接跳页。

## 决定
1. **后台接口（`/api/v1/admin/*` 的列表）改为页码分页**：查询参数 `page`（从 1 开始）、`page_size`（10/20/50/100，默认 20）；返回 `{items, total, page, page_size}`。POST 搜索类接口在请求体里带同样两个字段。
2. **小程序与其他 C 端接口继续游标分页**（手机端是滑动加载，游标更快，且翻页期间新增数据不会造成重复或遗漏）。
3. 两套都放在 `app/core/pagination.py`，统一复用：页码参数依赖 `Paging`，返回模型 `offset_page_model(XOut, "XPage")`，查询辅助 `paginate(db, stmt, params)`（一次 COUNT + 一次 OFFSET/LIMIT）。
4. 排序固定且包含唯一键（如 `id DESC`），保证翻页结果稳定。
5. 后台前端用一个通用分页表格：antd `Table` 的 `pagination`（总条数、每页条数选择、快速跳页），页码与每页条数写进网址查询参数（刷新不丢），筛选变化回到第 1 页。

## 代价
- 每次翻页多一次 COUNT；后台数据量下可以接受。将来某张表很大时，可只对该接口改用估算总数或限制最大页数。
- 翻页期间有新数据插入时，后台可能看到相邻页重复一条，属于页码分页的常见现象，管理后台可以接受。
