## 需求

用户在真机上调试小程序，陆续反馈下面八类问题，要求逐个修好。每条写成“现象 → 根因 → 修复”。

## 拆解

八个问题互相独立，分别修复、分别提交。另记 T029 的合入与历史数据回填。

## 方案与决定

### 1. 上传失败 80051（真机调试限制 2MB）

- 现象：真机上传照片失败，错误码 80051。
- 根因：真机调试对请求体有 2MB 上限。第一版（f1db1bb）按尺寸压缩，在真机上没有生效，原图仍然超限。
- 修复（1a2d2fe）：从源头取压缩图（`sizeType: compressed`，拍照画质 `normal`）；压缩时只调画质、逐级降低；压缩后仍超过 2MB 时明确提示用户，不再静默失败。

### 2. 相机权限“去设置里是空的”

- 现象：拍照时提示没有相机权限，去系统设置里找不到本小程序的相机选项（列表是空的）。
- 根因：之前把授权失败一律当作“用户拒绝”。实际原因是小程序隐私指引里没有声明摄像头（errno 112），或用户尚未同意隐私协议（errno 104），并不是用户拒绝。
- 修复（400788b）：先查授权状态，从没问过就直接弹系统授权；按失败原因区分提示；隐私弹窗在拍照页、引导页就地弹出。
- 需要用户做：在微信公众平台“用户隐私保护指引”里声明摄像头、选中的照片、相册（仅写入）。

### 3. 取景框太小，自拍放不进

- 现象：取景框太小，自拍时头放不进去。
- 根因：外框尺寸按证件照比例取得偏小。
- 修复（258af98）：外框铺满屏宽，头部轮廓约占屏宽 54%。

### 4. 没有倒计时自动拍照

- 现象：对准后没有出现倒计时，也不会自动拍。
- 根因：实时检测只要任一帧出错就降级，两种检测方式都失败后永久停止，并且没有任何提示；另外角度单位的假设（弧度或角度）可能不对。
- 修复（672d788）：连续 5 帧出错才降级；5 秒后重试；角度单位自动识别；增加诊断日志，前缀 `[实时检测]`。

### 5. 一直提示“离远一点/往上移”

- 现象：无论怎么调整都提示“离远一点”或“往上移”。
- 根因：相机帧坐标到屏幕坐标的换算在真机上不可靠。后端本来就会按人脸重新裁剪，前端不需要精确对准轮廓框。
- 修复（7f29c1e）：只在原始帧里判断大小（脸框长边 / 帧短边 在 0.2 到 0.78 之间算合适）；只有脸贴边时才提示“把整张脸放到框中间”；提示重点放在正脸、睁眼、光线。

### 6. 真机接口全部失败

- 现象：真机上所有接口请求都失败。
- 根因：小程序 API 地址是 localhost，手机访问不到；后端只监听 127.0.0.1。
- 修复（2ecbf9a 及后端配置）：
  - 新增 `pnpm dev:device`，把局域网地址写进 `.env.development.local`（Taro 只从 `.env` 文件读变量，所以不用环境变量传）。
  - 后端用 `--host 0.0.0.0` 启动，`PUBLIC_BASE_URL` 改成局域网地址。
  - 使用条件：手机与电脑在同一 Wi-Fi；iOS 打开“本地网络”权限；开发者工具勾选“不校验合法域名”。

### 7. 照片左右镜像

- 现象：拍出来的照片左右是反的。
- 根因：前置摄像头 `takePhoto` 默认镜像。
- 修复（e808e63）：设置 `selfieMirror: false`，证件照保持真实方向。

### 8. 精细抠图“没有最终效果”

- 现象：精细抠图前后两张图几乎一样，看不出效果。
- 根因：通用轻量版 BiRefNet 把身后的椅子当成了前景。
- 修复（679561f）：默认改用 BiRefNet 人像版（MIT 协议，模型约 972MB，CPU 约 12 秒/张，在后台运行）；可用 `FINE_MATTING_MODEL` 切换模型。
