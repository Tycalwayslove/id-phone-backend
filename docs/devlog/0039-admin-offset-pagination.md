# 0039 运营后台页码分页（T030）

- 日期：2026-11-20
- 状态：已完成，待 PostgreSQL 集成验证

## 需求

“运营后台现在是直接加载更多来加载下一页的数据，我需要那种正常管理后台的分页组件，可以直接跳转到指定页，以及自己去选择每页多少数据”。

## 拆解

1. 按 ADR 0008 统一后台分页参数、查询和返回结构。
2. 将后台列表、照片网格和服务商明细接入分页控件，并把页码与每页条数同步到网址。
3. 覆盖各接口第二页及总条数，重新生成接口文档和前端类型。

## 方案与决定

按 ADR 0008，后台按记录 ID 倒序分页。查询先按筛选条件计数，再读取单页记录。请求超过最后一页时，接口返回空列表及总条数，管理端将网址页码校正到最后一页。每页条数可选 10、20、50、100，默认 20。

## 改动

- 12 个后台列表接口改用 `page` 和 `page_size`，响应包含 `items`、`total`、`page` 和 `page_size`。用户手机号筛选继续通过 POST 请求体传送。
- 10 个管理端页面复用同一套分页逻辑。页码和每页条数写入网址，筛选和每页条数变动时回到第一页。服务商明细按服务商及表格区分分页参数。翻页期间继续显示旧数据和加载状态。
- 生成 OpenAPI 快照和管理端类型。12 个接口都补充第二页、总数和越界页的集成断言。

## 验证

Ruff、接口文档检查、管理端 `gen:api`、`typecheck` 和 `build` 通过。离线测试通过 217 项，另外 2 项需要本地照片模型。确认 OpenAPI 中 43 个后台操作 ID 和 C 端接口契约与原版一致。
