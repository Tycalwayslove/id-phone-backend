# 开发日志

每项需求一篇，文件名 `NNNN-简短英文名.md`，编号递增。写给“半年后接手的人”和“新开的 AI 会话”看：不看聊天记录，只看这里就知道发生了什么、为什么。

## 模板

```markdown
# NNNN 标题

- 日期：YYYY-MM-DD
- 状态：进行中 / 已完成 / 已放弃
- 相关提交：abc1234、def5678

## 需求
用户原话或需求要点（原话尽量保留）。

## 拆解
把需求拆成可以单独完成、单独验证的几步。

## 方案与决定
怎么做、为什么这么做；考虑过但没选的方案和原因。重要的另写 ADR。

## 改动
按模块列出新增或修改了哪些文件、表、接口、配置。

## 验证
怎么确认做对了：跑了哪些测试、CI 结果、手动检查了什么。

## 遗留与下一步
没做完的、已知问题、需要用户提供的东西（账号、密钥、资质）。
```
