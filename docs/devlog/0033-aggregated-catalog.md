# 0033 规格目录聚合与同步修复（T021）

- 日期：2026-11-19
- 状态：已完成，待用户本机同步
- 相关提交：a08390e（ADR 0006、任务单 T021、行政区划数据）、303e12d、47e2e10、15a8103、a44a180、4b566eb、025290b（PR #13，CI 全绿，355 个测试）

## 需求
用户原话：“现在同步规格会报错，提示回执服务商规格数据无效，我从这几个平台的api文档中看到是有很多规格的，而且我认为比较合理的交互是：用户先选城市，然后再去选自己想要的规格。有可能存在某种情况：某个服务商缺少这个规格，导致不展示。我希望的是：我将我对接的所有服务商所包含的所有规格服务都展示出来，当用户选择好，后续去调用的时候再去使用具体某个服务商的某个规格服务。这样，我的聚合平台才显得有意义。”

## 拆解
1. 查清同步报错的根因（用真实密钥只读调用接口确认）。
2. 修复适配器与同步；同步不再逐条调详情接口。
3. 跨服务商合并规格，同步后默认上架、建映射和路由规则。
4. 从名称识别地区，用户端按城市过滤，提供城市列表接口。
5. 后台筛选地区、同步时可选“自动上架”。
6. 开发库旧的重复规格合并脚本。
7. 小程序“先选城市”界面另开任务 T022。

## 根因（用真实密钥只读调用确认）
- 两家 `/item/list` 各 774 条，全部可解析，编号和内容一致。
- 同步对缺文件大小的条目逐条调 `/item/get`，真实格式与代码假设不同：鹧应的编号字段是 `item_id` 不是 `id`；黔微云外层多包了一层 `{"item": ...}`。第一条就失败，整次同步返回 503。而且详情里本来就没有文件大小。
- 另外 T019 按服务商各建一份规格、新规格默认下架且不建路由规则，导致“缺了就不展示”。

## 方案与决定
详见 `docs/adr/0006-aggregated-spec-catalog.md`，要点：
- 本地规格是面向用户的一项服务，与服务商无关；`provider_specs` 只记录“哪家能办、对方编号是什么”，一个规格可有多家映射。
- 同步时跨服务商合并：同上游按 `(upstream_group, 对方编号)`；不同上游按“规范化名称 + 像素宽高”；都没有才新建，编码 `cat_<上游或服务商>_<编号>`。
- 同步进来默认可用（可用 `auto_publish=false` 关闭）：规格上架、映射启用、自动建路由规则；已有规格、映射、规则的状态和优先级不覆盖。
- 地区从名称识别，写入 `specs.region_code`，识别不出视为全国通用；行政区划数据来源见 `backend/app/data/README.md`。
- 用户端选了城市后展示“全国通用 + 本省 + 本市”的规格；路由仍在提交时按优先级决定服务商。

## 改动
- 适配器：兼容真实详情格式；`ProviderItem` 增加 `is_receipt`、`receipt_fields`、`provider_category`；补充底色，`pose_*` 忽略，未知底色每次同步只汇总一条日志。
- 同步：不再逐条调详情；合并、分类、地区、回执表单（按 `receipt_param` 生成 `form_schema` 和 `param_mapping`）、`auto_publish`。
- 新增 `app/core/regions.py`、`app/data/regions.json`。
- 用户端接口：`GET /specs` 增加 `region_code` 过滤；规格输出增加 `region_name`；新增 `GET /spec-regions`（免登录）。
- 后台：规格列表地区筛选，编辑表单显示识别出的地区名，同步确认弹窗增加“同步后自动上架”勾选。
- 脚本：`backend/scripts/merge_catalog_specs.py`。

## 实际覆盖
- 124 条可办回执：主要是广东 21 个地市的身份证、社保、驾驶证、居住证、保安证，广东、贵州、安徽省级，以及港澳通行证、回乡证等全国通用项。
- 650 条普通照、签证照、报名照。

## 评审发现并修复
同步结果依赖服务商顺序：黔微云列表没有 `is_receipt`、`receipt_param`，先同步黔微云再同步鹧应与反过来结果不同。改为同步时从同上游服务商的目录补齐回执标记，并加了两种顺序的一致性测试。

该修复由 Opus 直接完成。原因：Codex 沙箱写不了 Git 索引；第二次改用 base64 bundle 交付时内容损坏、提交丢失；续接会话又是只读。已在记忆里记下：派 Codex 时要求只改文件、不提交。
