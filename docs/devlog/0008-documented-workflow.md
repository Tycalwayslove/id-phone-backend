# 0008 开发过程文档化与目标模式

- 日期：2026-11-19
- 状态：已完成

## 需求
- “你的改动最好有文档记录，将项目是怎么一步步运行的，每次需求的改动，做了哪些，包括需求拆解/实现，等等都给记录下来……后续换了人维护，或者换了电脑，AI 都清楚做了什么。这个也属于 AI 工作流的一部分。”
- “发挥主观能动性……前端/后端/数据库按主流商业公司的分层设计，一步步把功能都实现好。中途不要我任何确认，只想用目标模式，最后给我一个结果。”
- “可以多开几个 agent，架构和全局性的东西用 Opus，实现用便宜的 Sonnet。”

## 方案与决定
- 新增 `docs/`：README（文档地图）、progress（进度看板）、getting-started（本机运行）、devlog（每项需求一篇）、adr（设计决定）、product/requirements（业务规则精简版）。
- CLAUDE.md 的“工作方式”改为：目标模式、每项需求留记录、Opus 负责架构与评审 / Sonnet 子代理按模块实现、CI 为准。
- 跨模块调用约定写在 `backend/app/modules/CONTRACTS.md`，子代理只改自己模块目录，共享文件由主会话改。
- Claude Doc 的完整设计文档不导出进仓库（导出要逐字转写，容易出错）；仓库保留精简版并给出链接。
