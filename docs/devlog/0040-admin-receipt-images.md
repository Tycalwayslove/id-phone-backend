# 0040 后台回执详情展示图片（T031）

- 日期：2026-11-22
- 状态：已完成，待 PostgreSQL 集成验证

## 需求

“我看了下回执页面已经有一个回执 R20261118000001 了，但是对应的回执照片信息，并没有在运营后台展示，帮我展示一下。”

## 拆解

1. 为后台回执详情增加用户原图、每次提交的证件照和官方回执图，校验照片查看权限并记录审计。
2. 在回执详情展示可放大的图片和缺失原因，支持复制图像号。
3. 为开发库生成占位图片，验证详情契约、权限、审计和文件处理。

## 方案与决定

- 回执详情沿用 `application:read`。同时具备 `photo:read` 时，接口按当前照片、官方回执文件和各次提交的 `render_id` 读取图片，复用照片模块的 10 分钟签名机制。文件已清理或存储对象缺失时，接口返回空地址和原因。
- 每次成功读取详情写一条 `application.view` 审计。取消申请和登记核对结论的响应继续返回文字详情，图片通过详情 GET 获取。
- 演示数据沿用原有文件命名，官方回执改存 PNG。Pillow 生成剪影和“演示回执”，保留已存在的文件。

## 改动

- 回执抽屉顶部并排展示可放大的三张图，支持打开照片详情和复制图像号。提交记录按行显示对应缩略图和驳回原因。
- 更新跨模块合同和 OpenAPI，补充后台详情与演示文件测试。

## 验证

Ruff、接口文档检查、后台 `gen:api`、`typecheck` 和 `build` 通过。离线测试通过 222 项，另有 2 项因缺少本机照片模型跳过。测试覆盖签名、权限、审计提交、缺图原因、图片解码及保留已有文件。

## 遗留与下一步

当前沙箱拒绝连接本机 PostgreSQL，换照片后重提的端到端测试待有数据库的环境运行。开发库未重建。
