# 0001 需求梳理与分层

- 日期：2026-11-18
- 状态：已完成

## 需求
用户上传了一份 PRD：“基于这个需求定义，帮我确认需求，现今的需求不够明确，并且没有分层，跟我预想的有差异。” 之后通过 Claude Doc 评论补充了定价、规格、到期、AI 美化、多端、服务商、公司资质、一人开发、私域营销等细节。

## 拆解
1. 把 PRD 拆成核心链路（拍照 → 制作 → 购买 → 回执 → 保管下载）和外围（私域、冲印、手办、多端）。
2. 按分期整理：一期只做核心链路 + 后台。
3. 根据评论确定套餐、到期、驳回、一卡一人等规则。
4. 调研回执服务商（鹧应、黔微云、办证直通车、DT、证照家）。

## 方案与决定
- 套餐必须可配置（plans + plan_benefits），不写死在代码里。
- 回执覆盖范围取决于官方采集系统；鹧应与黔微云同一上游，不能互为备份。
- 营销只用手机号和企业微信好友，不用照片。
