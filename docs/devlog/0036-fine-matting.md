3. 扩展评估脚本并覆盖状态流转、缓存、渐隐和报告测试。

## 方案与决定

`MATTING_MODE=local` 时，创建照片先用 MODNet，事务提交后才将 BiRefNet 任务放入有界线程池。`FINE_MATTING_WORKERS` 默认 1，每线程另有一个等待位。定时 worker 每轮补做等待满两分钟的任务，使用 PostgreSQL advisory lock 防止 API 与 worker 同时推理同一张照片。

精细底片成功写入后更新 `matting_file_id` 和 `matting_level`。旧底片保留到删除照片时，以便正在导出的请求继续读取。导出缓存包含底片文件 ID，模型缺失或处理失败时保留原底片。上线前的照片和其他抠图模式返回空精度状态。

## 改动

- 迁移 `f17b93a4c280` 增加精度状态、任务入队时间和上一张底片的引用。
- 制作页每三秒查询一次精度，最长 60 秒。精细底片就绪后更新预览，保存时请求当前底片。
- 底部越界时用底色填充，并将原图下沿约 4% 成品高度的透明度线性衰减。
- 评估脚本支持 `--matting fast|fine|both`，报告列出检查项覆盖、逐项结果、实测明细和各模型的过检率。
