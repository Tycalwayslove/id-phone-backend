# 小程序界面 v2：先拍好看，再谈付费

- 日期：2026-11-19
- 状态：已定稿，由 T020 实现；2026-11-20 按用户反馈改为“先拍、后选证件”（第 7 节，T023）
- 范围：只改小程序前端（`miniapp/src/`），后端接口、价格、套餐都不变

## 1. 从用户出发

站在用户角度：我要一张身份证 / 社保卡 / 报名用的证件照，可能还要官方回执；我不想出门去照相馆。打开小程序时，我心里只有四个问题，按先后顺序：

1. **这里能做我要的那种照片吗？**（规格对不对、能不能办回执）
2. **拍出来好不好看？会不会被退回？**（核心顾虑）
3. **麻不麻烦？**（要不要白墙、要不要找人帮拍）
4. **要花多少钱？**（只有在前三个问题都满意之后才关心）

旧版首页把“套餐亮点”放在第三屏，一进来就在回答第 4 个问题，而前 3 个还没回答。很多人看到价格就走了。

**v2 的原则：页面的顺序跟着用户心里问题的顺序走。**

| 用户的问题 | 在哪里回答 | 怎么回答 |
|---|---|---|
| 能做我要的吗 | 首页搜索框 + 常用规格 | 直接列出常用规格，能办回执的标出来 |
| 好不好看 | 首页主视觉 + 制作页 | 主视觉演示“自动换底”；制作页按住就能对比原图，美颜可调 |
| 麻不麻烦 | 首页一句话 + 拍摄前提示 | “不用找白墙，背景自动换”；拍前三条提示 |
| 多少钱 | **只在点“保存高清照片”时** | 底部弹出保存面板，讲清楚花这笔钱能得到什么 |

关键承诺：**先免费看成品，满意再保存。** 这句话在首页主按钮下方出现，用来打消付费顾虑，但首页不出现任何价格。这句话是真实的：未付费用户可以无限次生成带水印的成品预览（后端现有规则）。

## 2. 四个优势怎么体现

不做成一块广告式的“优势卖点”区，而是让每个优势出现在用户最在意它的那一刻：

| 优势 | 用户在意的时刻 | 体现方式 |
|---|---|---|
| 照片更好看 | 第一眼、制作时 | 首页主视觉；制作页“按住对比原图”、美颜“自然 ↔ 精致”可调 |
| 无广告 | 全程 | 不做弹窗、不强制登录、不放任何推广位，用克制的界面本身证明；首页优势说明里写一句 |
| 全国覆盖 | 选规格时 | 规格卡片标“可办回执”；首页“办回执”一节说明各省身份证、社保卡、驾驶证等都能在线办 |
| 云端保管 | 付费时、回来找照片时 | 保存面板里写“保管 N 天，换手机也能下载”“同一张照片免费换其他尺寸”；“我的照片”显示保管到哪天 |

首页底部有一段“为什么在这里拍”，按用户在意程度排序：修得自然 → 没有广告 → 全国可办回执 → 云端保管。每条一句大白话，不用数字吹嘘（我们没有可信的统计数字，不编）。

## 3. 视觉系统

### 3.1 主题：证件照本身

视觉素材都取自证件照这件事本身：三种标准底色（白、蓝、红）和照相馆裁切照片用的**裁切角标**（四个角上的 L 形线）。

**整个界面唯一的“记忆点”是“相框”**：一个按证件照比例的竖向框，四角有裁切角标。它出现在首页主视觉、制作页预览、我的照片缩略图上。其他地方保持安静。

### 3.2 颜色（写成 `app.scss` 里的 CSS 变量）

| 变量 | 值 | 用途 |
|---|---|---|
| `--c-ink` | `#17233B` | 标题和正文主色（墨蓝，比纯黑柔和） |
| `--c-primary` | `#2F6CC8` | 主按钮、选中态、链接（证件蓝加深，白字对比度够） |
| `--c-backdrop-blue` | `#438EDB` | 标准证件蓝底，只用于主视觉和底色色块 |
| `--c-backdrop-red` | `#D7263D` | 标准证件红底，只用于主视觉和底色色块 |
| `--c-bg` | `#EEF1F5` | 页面底色（冷灰） |
| `--c-surface` | `#FFFFFF` | 卡片、面板 |
| `--c-text-2` | `#5B6577` | 次要文字 |
| `--c-line` | `#DDE2EA` | 分隔线、裁切角标 |
| `--c-ok` | `#1F8A5B` | “已保管”“可办回执”等正向状态 |
| `--c-danger` | `#D93A3A` | 错误（和证件红区分开） |

NutUI 主色跟随 `--c-primary`。旧变量名（`--c-text`、`--c-success` 等）保留为别名，避免漏改的页面失色。

### 3.3 字体与字号

用系统字体（苹方），不加载自定义字体（小程序包体积和加载速度优先）。字号（750 设计稿 px）：

| 用途 | 字号 | 字重 |
|---|---|---|
| 首页主标题 | 52 | 600 |
| 页面/面板标题 | 36 | 600 |
| 小节标题 | 32 | 600 |
| 正文 | 28 | 400 |
| 辅助说明 | 24 | 400 |
| 价格数字 | 44 | 600，`font-variant-numeric: tabular-nums` |

正文左对齐；只有主视觉区域居中。

### 3.4 形状与层级

- 主按钮：高 96，圆角 16，填充 `--c-primary`；次按钮：白底 + 1px `--c-line` 描边。
- 卡片圆角 20；底部弹出面板顶部圆角 32。
- 不给所有东西都套卡片：首页的说明性内容直接放在页面底色上，只有可点的规格格子是卡片。
- 阴影只用在底部操作栏和弹出面板上。

### 3.5 动效

全局只有一处自动播放的动效：首页主视觉相框里人像剪影的背景按 白 → 蓝 → 红 慢慢淡入切换（每 2.4 秒一次），演示“背景自动换”。其他动效只在用户操作时出现（面板弹出、选中切换）。

### 3.6 文案规则

- 从用户角度说话，用大白话：“保存高清照片”而不是“购买套餐”；“换个尺寸”而不是“更换规格”。
- 按钮写清点了会发生什么；同一个动作全程用同一个名字（按钮“保存高清照片” → 成功提示“已保存到相册”）。
- 不用“·”拼接信息串，不用全大写标签，不在标题上加小标签，按钮不加“→”。
- 空状态告诉用户下一步做什么。

## 4. 页面与流程

### 4.1 主流程

```
首页 ─ 点“开始拍” ─▶ 选规格面板 ─▶ 拍摄提示面板 ─▶ 拍照/相册 ─▶ 制作页
首页 ─ 点某个常用规格 ───────────▶ 拍摄提示面板 ─▶ …
首页 ─ 搜索 ─▶ 规格列表 ─▶ 规格详情 ─▶ 拍摄提示面板 ─▶ …
制作页 ─ 点“保存高清照片” ─(未付费)─▶ 保存面板（这里才出现价格）─▶ 支付 ─▶ 自动存相册
```

- 删除“套餐亮点”一节。首页不出现价格。
- 常用规格：`listSpecs({ limit: 8 })`，顺序由运营在后台的排序值决定。
- 主视觉剪影用 CSS 画（头部圆 + 肩部圆角矩形），**不用真人照片**（没有授权的人像素材，不能编造）。

### 4.3 选规格面板（新组件 `SpecPicker`）

底部弹出。标题“拍哪种证件照？”，复用常用规格格子 + 一个“搜索更多规格”入口（跳规格列表页）。点选规格后直接进入拍摄提示面板。

### 4.4 拍摄提示面板（新组件 `ShootGuide`）

底部弹出，标题“拍之前看一眼”，三条（这是步骤性内容，用编号合理）：

1. 正对镜头，露出眉毛和耳朵，表情自然
2. 光线均匀，脸上没有明显阴影
3. 不用找白墙，背景会自动换成 {规格默认底色名}

下方两个按钮：“拍照”（主）、“从相册选”（次），以及“下次不再提示”勾选（存 `Taro.setStorageSync`，勾选后直接弹系统选择）。规格详情页底部按钮也走这个面板。

### 4.5 制作页（重点改）

```
┌──────────────────────────────┐
│        ┌┐            ┌┐        │
│        │   成品预览     │  ← 相框
│        └┘            └┘        │
│      按住照片对比原图              │  24 次要色
│ 身份证  358×441 像素  符合官方尺寸  │
├──────────────────────────────┤
│ 底色   ● 白  ● 蓝  ● 红           │  色块 + 文字名
│ 美颜   自然 ○─○─●─○ 精致          │  分段，0..beauty_max
├──────────────────────────────┤
│ 预览带水印，保存后是高清无水印照片    │  （未付费时显示）
│ [办理回执]   [   保存高清照片   ]   │
└──────────────────────────────┘
```

- **按住对比原图**：`onTouchStart` 显示 `photo.original_url`，`onTouchEnd`/`onTouchCancel` 恢复成品。这是“修得好看”最直接的证据。
- 底色色块下加中文名：`#FFFFFF` 白、`#438EDB`（及相近蓝）蓝、红系 红，其他显示“其他”。写成 `utils/format.ts` 的 `bgColorName(hex)`。
- 美颜改成“自然 … 精致”两端标注的分段选择（仍是 0..`beauty_max` 的整数）；`beauty_max = 0` 时显示“该规格官方不允许美颜”。
- 主按钮“保存高清照片”：
  - 已付费（`access.active`）：直接保存到相册（现有 `saveRenderToAlbum`）。
  - 未付费：打开保存面板。
- “办理回执”只在规格支持回执时显示，作为次按钮。
- 去掉旧的“购买套餐”按钮文案。

### 4.6 保存面板（新组件 `UnlockSheet`）——唯一出现价格的地方

```
┌──────────────────────────────┐
│ 保存这张照片                        │
│ ✓ 高清无水印，可直接用于报名和办证     │  固定第一条
│ ✓ 云端保管 30 天，换手机也能下载      │  ┐ 随选中的套餐变化
│ ✓ 含 1 次官方回执，被驳回免费重提 3 次 │  ┘（示例：身份证规格，选中 19.9 档）
├──────────────────────────────┤
│ ● 单次精修 + 回执  推荐   ¥19.9      │
│ ○ 单张照片年度保管         ¥39.9      │
│ ○ 年度不限次               ¥99       │
├──────────────────────────────┤
│ [          支付 ¥19.9          ]   │
│ 支付即同意《用户协议》               │
└──────────────────────────────┘
```

- 可选套餐：`listPlans()` 里 `price_fen > 0`、`attach_to_parent = 0`、`storage_days > 0` 的套餐（加办类不在这里出现）。
- 默认选中（“推荐”标签）：规格支持回执 → 含回执次数的套餐里最便宜的；不支持回执 → 不含回执的套餐里最便宜的，没有则全部里最便宜的。规则写成纯函数 `pickRecommendedPlan(plans, supportsReceipt)`，便于以后调整。
- 权益文案由 `benefits` 生成（纯函数 `describeBenefits(plan)`，放 `utils/plans.ts`，`PlanCard` 和本面板共用）：
  - `storage_days`：365 的整数倍显示“N 年”，否则“N 天”→“云端保管 N 年/天，换手机也能下载”
  - `spec_change = 1` →“同一张照片免费换其他尺寸”
  - `photo_scope = 0` →“期内不限照片张数”
  - `receipt_quota > 0` →“含 N 次官方回执”；`resubmit_limit > 0` 时追加“被驳回免费重提 N 次”
- 支付成功后：关闭面板 → 重新取照片权益 → 重新生成无水印成品 → 自动保存到相册 → 提示“已保存到相册”。支付取消不提示错误。
- 下单与支付逻辑从套餐页抽成 `hooks/usePurchase.ts`，套餐页和保存面板共用，行为不变（幂等键、`requestPayment`、轮询、fake 支付）。

### 4.7 我的照片（原“证件照”tab，改名）

- tab 文字改为“我的照片”，页面标题同。
- 缩略图用相框样式；状态：已付费“保管至 2027-11-19”（绿色），已过期“已过期，续费后可下载”，未付费“预览，未保存”。
- 空状态：“拍好的照片会存在这里”，按钮“去拍一张”（打开选规格面板）。

### 4.8 我的

- 列表顺序：我的回执、我的订单、我的权益、价格说明（即套餐页，不再在首页推广）、联系我们（私域卡片）、用户协议、隐私政策。

### 4.9 其他页面

规格列表、规格详情、回执、订单等页面不改结构，只跟随新的颜色和字号变量；规格详情底部按钮改为打开拍摄提示面板。

## 5. 不做的事（以及原因）

- 不改价格和套餐内容：用户反馈的问题是“价格出现得太早”，不是“价格本身”。
- 不加 tab 图标：仍是纯文字（之前的决定）；要加需要设计图标素材，另开任务。
- 不做新手引导轮播、不做开屏：都是用户还没看到价值前的打扰。
- 不用真人示例照片：没有授权素材；以后有授权的模特样片再加到主视觉。

## 6. 验收

- 首页、选规格、拍摄提示、制作页、保存面板走通（fake 支付），首页不出现任何价格。
- 制作页按住能看到原图，松开恢复。
- 小程序 typecheck、build 通过，CI 全绿；用户在微信开发者工具里真机看一遍。

## 7. 修订（2026-11-20）：先拍好看，再选证件

用户在真机上试用后的反馈：“现在点击开始拍，要先选城市和证件名称，我觉得不好……先把照片拍的好看这个核心点完成，再去说后续的证件业务。因为如果证件不好看，那后续用户付费的意愿可能就不高了。”

判断：成立。照片本身和规格无关，套餐也绑定在照片上；规格只决定最后的尺寸、底色要求和能否办回执。所以把“选证件”从拍摄之前挪到“修好看之后、保存之前”。

### 7.1 新的主流程

```
首页“开始拍” ─▶ 拍摄提示 ─▶ 拍照/相册 ─▶ 制作页（第 1 步：修好看，用默认的“一寸”比例预览）
                                          │ 满意了，点“选证件类型”
                                          ▼
                              城市面板（可跳过）─▶ 选规格面板 ─▶ 制作页（第 2 步：按所选证件重新生成）
                                                                    │
                                                    “保存高清照片”（这里才出现价格）/“办理回执”
首页点某个规格（已经知道要什么的人）─▶ 拍摄提示 ─▶ 拍照 ─▶ 直接是第 2 步（保留这条快捷路径）
```

- “开始拍”不再弹城市和规格面板。城市只在用户去选证件类型时才问，仍可跳过。
- 默认预览规格由后端决定（`GET /specs/preview`，见 T023），小程序不写死。

### 7.2 制作页两步

第 1 步“修好看”（还没选证件）：
- 预览、按住对比原图、底色、美颜（按默认规格的上限），和原来一样。
- 证件信息行写“还没选证件类型，先把照片修满意”。
- 底部只有一个主按钮“选证件类型”。不出现保存、价格。

第 2 步（已选证件）：
- 证件信息行写“{证件名} {宽}×{高} 像素”，右侧“换一个”。
- 换证件时保留用户选的底色和美颜；新证件不允许时自动调整，并用一句话说明原因：
  - 底色：“{证件名}要求{颜色}底，已自动换成{颜色}底”；
  - 美颜：“{证件名}官方不允许美颜，已关闭”或“{证件名}最多允许 N 档美颜，已调到 N 档”。
- 底部：“保存高清照片”（主）+“办理回执”（证件支持回执时）。后续与第 4.5、4.6 节相同。

### 7.3 底色数据统一

seed 建的规格底色存成了英文名（`blue`/`white`/`red`），同步进来的存的是十六进制色值。统一成十六进制（数据修复脚本处理 seed 库，seed 脚本改为写色值）；小程序 `bgColorName` 同时兼容两种写法，避免旧数据显示异常。
